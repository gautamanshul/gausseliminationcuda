## New Variants

### V6e

`V6e` is the P4/P5 structural variant. It adds a panel-level factorization
kernel and defers row swaps outside the active panel.

Within each panel:

1. `factor_panel_v6e_kernel` performs pivot search, RHS swap, panel-local row
   swap, multiplier computation, and in-panel rank-1 updates inside one CUDA
   kernel launch.
2. `apply_deferred_swaps_v6e_kernel` applies the recorded panel pivots to
   columns outside the active panel in one grid-wide launch.
3. cuBLAS `STRSM` computes `U12`.
4. cuBLAS `SGEMM` updates `A22`.
5. cuBLAS `STRSV` solves the final triangular systems.

This reduces the per-pivot launch ladder and moves the custom panel path closer
to the blocked LU structure used by LAPACK/MAGMA/cuSOLVER-style algorithms.

### V5c

`V5c` is the P6 rank-b tiled-update experiment. It keeps the V6c-style fused
panel path but replaces the trailing `A22 -= L21 * U12` cuBLAS `SGEMM` call
with `rank_b_update_v5c_kernel`, a 16x16 shared-memory CUDA kernel.

The purpose is empirical: V5 showed that tiling does not help a rank-1 update.
V5c asks whether the same tiling idea becomes useful once the update is raised
to rank-b. On this GTX 1650 run, the answer is nuanced: the custom rank-b
kernel is correct, but it does not beat cuBLAS `SGEMM`.

## Interpretation

P4/P5 produced a correct single-panel/deferred-swap path and substantially
reduced small-size overhead. At `n=4096`, however, this first V6e implementation
is close to but not faster than the optimized V6c path in a single run. This
suggests that reducing launch count helps, but a one-block panel kernel can
become the new bottleneck as size grows. The result is still valuable because
it converts the review's structural recommendation into a measurable variant.

P6 is a clean negative result: rank-b tiling is algorithmically more reusable
than rank-1 tiling, but a simple custom tiled kernel does not match cuBLAS
`SGEMM` on this consumer GPU. For the dissertation, this strengthens the
transferability story: raising arithmetic intensity is necessary but not
sufficient; mature vendor kernels still matter.
